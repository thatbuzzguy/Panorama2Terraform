# Acceptance — F1.3: Generator golden-file tests

## Purpose
Pin the current TerraformGenerator output byte-for-byte so the Epic 2
provider-v2 rewrite shows as a deliberate, reviewable golden-file update
instead of an invisible behavior change.

## Scope
- Drive `TerraformGenerator` directly (not the CLI) from:
  - the sample config (full pipeline: all object/rule/profile types), and
  - a fixture that exercises paths the sample never hits (virtual routers,
    logical routers, IPsec tunnels, IKE/IPsec crypto profiles, schedules,
    app filters, app override rules, PBF, decryption, zones, interfaces,
    log settings, QoS, tunnel monitors, BGP, OSPF).
- Commit the generated `.tf` files as golden files under `tests/golden/`.
- One test per generated file: generated bytes must equal golden bytes.
- Tests must run offline.

## Non-goals
- No Terraform validation (F1.5).
- No provider-schema checks (F1.4).
- No changes to generator behavior in this task. The goldens pin current
  output, including known v1-style schema issues.

## Done when
- `pytest` runs the golden-file tests and they pass offline.
- Golden files are committed and diff-able in review.
- `ruff check .` clean.
- Sample-config golden matches a fresh CLI run (cross-check the two entry
  points produce identical bytes).
- Committed with an ASD-STE100 message.
