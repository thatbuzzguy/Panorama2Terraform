# Acceptance criteria — F6.10.2: the print site per unit

Feature record: `PLAN.md` Epic 6, `to-do.md` slice 2 of F6.10. The print-site rule is decided
(`docs/CODEBASE_ASSEMBLY.md` §5 rule 5, F6.9); this slice runs that rule per unit at the print site.
It writes no directory, so no directory appears in the output: the pin that says no unit directory is
written yet stays green, and the directory write stays with F6.10.3.

Scope: one rule, one place. `TerraformGenerator.name_ref` is the single reference rule; `naming.py` is
the single naming rule; the unit is read through `unit_manifest.facts_of`. The `references` gate rule
needs no change, because a plain name is not a block reference. No new gate rule, no new CLI argument.

## Decisions

### 1. The rule runs per unit

1. **A name the referrer's own unit declares is a reference.** `name_ref` resolves a name inside the
   unit the referrer belongs to, so it returns `HclRef('<scope>.<local>.name')`.
2. **A name another unit in the run declares is a plain string.** One plan runs against one root and
   one state (§1 rule 3), so a block address in one unit cannot name an address another unit declares.
   The value the provider reads is the name itself, which Panorama resolves through its own inheritance
   at commit time. This is the decided mechanism, so this slice states no new mechanism.
3. **A name no unit in the run declares** keeps the F5.5 rule: a read-through `data` block when the run
   opted the scope in, else a plain string. The read-through branch serves a name outside the codebase,
   so it does not run for a name one unit declares and another unit uses.
4. **The context chain, the vsys chain, the flat first-declaration index and the device index are one
   rule now.** Each of them resolved a name across scopes, which is the case rule 2 decides as a plain
   name. So the per-unit lookup replaces them, and no second reference rule is left: the device case is
   a per-unit case, not a separate order step.
5. **The record rule is unchanged.** `name_ref` still records every name it resolved outside the unit —
   a plain string or a read-through block — against the referrer's four scope facts, so the manifest
   `references` field and the edge record name every cross-unit use.

### 2. One unit rule at both sites

The declaring site records the unit through `unit_manifest.facts_of`, at the site that applied the naming
rule, the same way `record_import_row` does. The reference site reads the unit through the same function
from the referrer object it already passes. So the rule has no second key for a unit, and no module other
than the print site decides the shape of a reference.

The digest is unchanged: `declare_block_name` keeps the identity key the naming rule states, so a local
name does not move, and only the reference shape changes.

## Acceptance criteria

1. `name_ref` returns a `.name` reference only for a name the referrer's own unit declares, and the plain
   name for a name another unit declares. The rule is pinned at the print site in `tests/test_robustness.py`
   and `tests/test_data_blocks.py`, and the per-unit pins replace the pins that measured a cross-unit
   resolution (`tests/test_robustness.py`, `tests/test_multi_device_template.py`,
   `tests/test_multi_vsys_location.py`).
2. Every call site passes the object the site belongs to, so the rule can read the unit through
   `facts_of`; no call site names a context, a vsys or a device, because the referrer states them.
3. `CORPUS_EDGES` (`tests/test_reference_edges.py`) and `GROUPING_REFERENCES`
   (`tests/test_unit_manifest.py`) are re-measured from a real run: each list is the output of the corpus
   run the test performs, printed and copied, not written by hand. The rules that hold them and the test
   bodies that measure them do not change.
4. `tests/fixtures/reference_cycle.xml` still produces two edges and one cycle finding, because the referrer
   entry and the declaring entry are in different units, which is what the fixture comment states.
5. A single-unit run writes the same bytes as before. A multi-unit run writes the same bytes except where
   a reference crossed a unit boundary. Both committed golden sets are regenerated by running the converter
   on the two pinned sources — not edited by hand — so the golden pin reads a real run.
6. The gate is unchanged: `check_references`, `check_data_blocks`, `check_variables`, `CHECK_ORDER`, the
   report counts and the exit codes keep their pins; no rule reads a unit directory, because none is written.
7. `test_the_mechanism_defines_no_writer_and_no_reader` stays green: no module defines an outputs writer or
   a remote-state reader, and no module docstring carries a word the scan forbids.
8. `unit_manifest.py` and `reference_edges.py` still resolve no name and record no name; `import_blocks.py`
   still defines no naming rule and no location rule, so `def name_ref` and `def declare_block_name` stay in
   the print site.
9. `docs/ARCHITECTURE.md` §4.3 states the order as the per-unit rule, and names the tests that hold it;
   `docs/CODEBASE_ASSEMBLY.md` §5 rule 5 stays the owner of the mechanism decision and gains the sentence
   that the step has run. No new document restates the rule.
10. `ruff check .` is clean, `python3 -m pytest` is green, and the change is committed with an
    ASD-STE100 message that starts `F6.10.2:`.
